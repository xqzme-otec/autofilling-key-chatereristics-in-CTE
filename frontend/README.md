# Фронтенд заполнения характеристик СТЕ

Интерфейс отправляет описание товара в сервис-агрегатор и показывает его ответ: исправления, характеристики, ошибки, кандидатов КТРУ и историю сужения. Если агрегатор возвращает `next_step`, выбранный вариант отправляется в текущую сессию. Итоговый код показывается только из поля `ktru` ответа API.

## Запуск

Сначала запустите агрегатор на `http://127.0.0.1:8000` и его модельный сервис. Затем:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://127.0.0.1:5173`). В режиме разработки запросы `/api/*` перенаправляются на агрегатор. Если он слушает другой адрес, задайте `API_PROXY_TARGET`, например:

```bash
API_PROXY_TARGET=http://127.0.0.1:9000 npm run dev
```

Для сборки используйте `npm run build`. Если страница открыта на `localhost` или `127.0.0.1` (в том числе через Docker на порту 8080), фронтенд всегда отправляет запросы на `/api/*` своего локального адреса. Vite перенаправляет их на локальный агрегатор на порту 8000, а Docker — на сервис `backend` внутри Compose. Значение `VITE_API_BASE_URL` на локальном адресе игнорируется.

На опубликованном сайте запросы идут на `/api/*` того же сайта. Если опубликованный агрегатор расположен на другом домене, задайте его адрес в `VITE_API_BASE_URL` **при сборке** фронтенда, например `VITE_API_BASE_URL=https://api.example.com npm run build`. Агрегатор должен разрешать origin фронтенда через `CORS_ORIGINS`.

API-контракт описан в [`docs/api.md`](../docs/api.md). Поле `characteristics[].source` содержит технический источник
(`ktru`, `portal` или `user`), исходный фрагмент находится в `characteristics[].user_text`. Происхождение по иерархии
КТРУ / Портал / новая / ответ передаётся в `characteristics[].origin` и показывается в интерфейсе. Сохранение
карточки СТЕ в API не предусмотрено.

## Проверка

```bash
cd frontend
npm run build
```

Для ручной проверки введите описание, нажмите «Подобрать характеристики», выберите ответ на уточняющий вопрос и убедитесь, что появился код из ответа агрегатора. Без работающего модельного сервиса агрегатор вернёт ошибку — интерфейс покажет её, сохранив описание в поле.
